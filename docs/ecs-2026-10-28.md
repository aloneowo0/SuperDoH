# ECS cloud acceptance — 2026-10-28

`DNS_ECS` adds explicit client/fixed ECS policy to selected `queryUpstream` actions. It is disabled by default. No production binding was added; existing endpoint and environment bindings remain unchanged.

## Results

Three client requests invoked the bounded cloud suite, within the 40-request allowance; no local behavioral suites were run. The final suite passed **31 of 32 checks**. The runner intentionally exits unsuccessfully for the remaining real-resolver boundary assertion: Google returned **REFUSED (RCODE 5)** for the reserved documentation subnet `203.0.113.0/24`, with no A answer. This is not presented as a complete pass or evidence of successful geographic optimization. No real visitor address was substituted.

Passed checks include IPv4 /24, IPv6 /56, non-byte /17 masking, fixed CIDR normalization, incoming /0 and stricter prefix limits, malformed/duplicate/noncanonical ECS rejection, response identity matching, restoring client ECS with actual upstream scope, no internal ECS leakage, untrusted headers ignored, default-off and upstream allowlist isolation, DO/AD/other OPT/extended RCODE preservation, explicit rejection of unrepresentable extended RCODE without client OPT, optional rollback, queryEch isolation and cancellation.

The real Workers Cache API reused the same subnet's response while querying the fixture once for each of two different subnets. Both source events and stats were observed in FRA in the same isolate. This is local cache evidence, not a globally durable/shared-cache guarantee.

## Harness corrections and retained failures

The initial fixture deployment failed Cloudflare validation because randomness was generated at module scope; initialization was moved into its handler. Earlier suites failed cache statistics because Workers does not support `redirect: 'error'`; the harness now uses `manual` and rejects 3xx explicitly. The original and second-attempt records are retained in the result report. The final runner still failed only the Google assertion. Windows Node also emitted a libuv shutdown assertion after the runner threw; the HTTP results had already been saved and are not a successful runner exit.

The tracked, secret-free harness templates are in `test/cloud/ecs/`. Runtime bundles, actual access guards and immutable request ledgers remain under ignored `.acceptance/ecs-20261028/`. Build with `node test/cloud/ecs/build.mjs`; provision only isolated temporary configurations before any deployment. Both temporary Workers were deleted and independently absent from the account listing after this run.

## Boundaries

- No production ECS opt-in; enabling client subnet disclosure remains a separate choice.
- Google success with a useful geographic subnet has not been established by this reserved-address test.
- ECS does not proxy traffic, guarantee Meta/X reachability or guarantee ECH acceptance.
- Public TCP ECS and browser behavior were not newly tested. The implementation uses the existing shared HTTPS/TCP outgoing query boundary.
- Local validation was limited to syntax, TypeScript, whitespace and offline bundling.
