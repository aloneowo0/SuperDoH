# SuperDoH 重构规划

日期：2026-10-19。
状态：用户已确认访谈结论；已整理为 [正式规格](specs/2026-10-19-custom-dns.md)。测试接缝已确认，规格已发布为 [GitHub Issue #7](https://github.com/aloneowo0/SuperDoH/issues/7)。本文保留最终需求与分阶段规划，不作为当前能力清单。

2026-10-20 实施进度：T1 / #8、T2 / #9、T3 / #10 已分别在 `26befc2`、`72b919b`、`2f895ce` 提交，公共执行入口、动作回滚/失败事件、组合条件已通过本地验收。当前可用接口、限制和测试说明见 [规则执行器文档](rules.md)。正式 DoH、上游、缓存及其他后续切片仍未交付；没有执行部署或线上免费 CPU 配额验收。
领域词汇见 [CONTEXT.md](../CONTEXT.md)。

## 目标与约束

- 建立可自定义的 DNS 服务，而不是移植旧版业务实现。
- 不默认继承旧功能。新功能以本次确认的模型和范围为准。
- Cloudflare Workers 免费套餐为硬约束；线上 CPU 验收不可用本地经过时间替代。
- 单部署、单配置，所有调用者共享规则；不建立多用户账户或多配置系统。
- 复用独立的 DNS WASM 和 ECH 探测库，保持库的通用性。
- 不默认加入旧版前端、伪装入口、CDN 自动分类或厂商专用策略。

## 规则与配置

- 规则集由有序规则组成，每条规则包含匹配条件和有序动作列表。
- 条件不按少数业务场景收窄，支持组合查询、请求上下文、当前解析结果等可用信息。
- 数据只有取得后才可用于匹配；尚未查询上游时不能假定存在上游答案。
- 配置只使用 Workers 环境变量，不保留文件配置作为回退；每个规则组独立保存为 JSON 变量，并带排序参数。
- 规则组按显式排序参数执行，组内规则和动作按数组顺序执行；具体格式已由正式规格及 T1 落实：DNS_RULE_ 前缀、order 升序，同序号按变量名 ASCII 字典序排序。
- 声明式为主；自定义条件与动作函数在代码中注册，由 JSON 配置通过名称和参数引用，不把字符串当作代码执行。
- 公共配置同样由环境变量提供；敏感值使用 Secret。错误配置应明确报告，不静默跳过规则组或回退到文件。
- 设计须考虑单变量 5 KB、免费套餐普通变量与 Secret 合计 64 个的限制。
- 扩展代码来自部署者维护的配置，不接受请求方上传或运行时求值的代码。
- 顺序处理：一条规则命中后按顺序执行其动作，再判断后续规则。
- 后续规则读取当前状态；另行保留原始查询和取得的上游原始响应供显式引用。
- 同一字段由多个成功动作修改时，后执行的修改生效。
- 查询上游也是动作，可以与生成自定义记录、改写响应、调整 TTL 等组合。
- 后续规则可检查查询结果并按配置再次查询；不隐式重复查询或默认竞速所有上游。

### 域名条件

- 域名匹配是规则的一等能力，可与 IP、ASN、地区、查询类型等条件组合。
- 区分当前查询域名、原始查询域名和响应中的域名字段，不使用含义不明的统一 domain 属性。
- 精确、域名后缀、通配符和正则匹配的具体操作符及边界在规则格式中明确；本节不把尚未确认的语法当作已实现 API。
- 匹配域名不隐式发起 DNS 或 HTTP 查询。
- 域名可直接配置，也可引用显式配置的外部 HTTPS 域名列表；环境变量保存来源描述，不必容纳整个列表。
- 外部列表的获取、缓存和更新应显式配置，不在每次条件匹配时下载。
- 外部列表作为域名数据，不自动成为可执行代码或远程动作配置。
- 第一版支持纯文本一行一个域名及 JSON 域名数组，不承诺兼容 hosts、Adblock 或 Clash/Mihomo 规则语义。
- 更新间隔用于决定何时检查来源，不将其混同于 DNS 记录 TTL。
- 列表更新失败直接判定该来源不可用，不继续使用旧版本作为回退；旧数据物理上仍存在也不得继续用于匹配。
- 首次加载失败、下载失败或新内容校验失败均需明确报错；不得当作空列表或静默跳过依赖规则。
- 失效影响依赖该来源的处理，沿用显式失败策略和错误日志；不能因为列表不可用就把条件判断为普通未命中。
- 后续成功下载并完整校验后才恢复来源可用状态；缓存与不可用状态的跨实例可见性需在实现时明确，不能宣称内存缓存全局一致。

### IP、ASN 与地区条件

- 同时支持客户端和 DNS 响应地址的 IP、ASN、地区匹配，不把两者混为一谈。
- 地区字段按国家/地区、省级行政区、城市等具体含义区分；字段可能不可用，不推断不存在的精度。
- 客户端网络信息与 Cloudflare 边缘节点位置分别命名；边缘位置不等于客户端位置。
- Workers 入站元数据可提供客户端 ASN、国家等信息；DNS 响应 IP 的 ASN 和地区需要额外数据源。
- 响应中可以有多个地址，条件设计必须明确逐地址关联，避免将一个地址的 ASN 与另一个地址的地区拼成命中。
- 响应地址的 ASN/地区补全作为显式动作，数据源由配置指定并可缓存；匹配条件本身不隐式联网。
- 补全失败遵循动作失败策略，并记录错误；缺失属性不伪装成已取得的值。具体数据源适配仍待实现设计。

### 终止与默认处理

- 默认执行后继续。
- 支持显式停止后续规则，并保留当前处理结果。
- 支持明确返回已生成或已选定的响应；直接返回不应隐式再查询上游。
- 正常结束规则处理后仍无答案时，使用默认上游；默认上游失败返回 SERVFAIL。
- NOERROR 空答案或 NXDOMAIN 是已有 DNS 响应，不等于“尚无答案”。
- 规则调用和网络操作必须有资源边界；不承诺任意扩展代码都能在免费 CPU 配额内运行。

## 失败、回滚和日志

- 默认动作是必需动作：失败终止本次 DNS 处理，返回 SERVFAIL。
- 可显式配置动作失败后继续。
- 可选动作失败时，回滚该动作对 DNS 处理状态的修改，再继续。
- 不回滚之前已成功的动作，也不声称能撤销网络请求或已经写出的日志。
- 失败绝不静默：记录请求标识、规则与动作标识、错误码、错误信息及后续处理结果。
- 日志明确区分：终止、已回滚并继续、上游回退；不得把失败伪装为成功。
- 隐藏访问密钥、凭据和携带密钥的完整请求路径；不默认输出完整 DNS 报文。
- 自定义动作的状态写入也应受回滚契约约束，不能仅对内置动作提供回滚。

## 客户端接口与访问控制

- 标准 DoH：RFC 8484 GET/POST、application/dns-message。
- JSON 查询/响应作为可选适配入口，复用同一 DNS 处理核心，不建立另一套规则语义。
- 访问控制可选：配置访问密钥时启用，未配置时允许公开使用。
- 密钥通过路径携带，例如 /<密钥>/dns-query；不要求客户端自定义 Authorization 请求头。
- 密钥来自 Workers Secret，不写入配置源码、测试快照或仓库。
- 应用日志脱敏不代表客户端或外部代理一定不会记录含密钥地址。

## 上游查询

- 第一版使用标准 DoH 上游。
- 命名上游组支持单上游、顺序回退和并发竞速，由动作引用。
- 成功条件可修改，并提供默认值。
- 默认接受合法 NXDOMAIN 和 NOERROR 空答案；网络错误、无效协议响应、SERVFAIL 等进入失败判断。
- 竞速采用首个满足成功条件的 DNS 响应，而不是首个 HTTP 200。
- 有效性检查必须先于自定义成功判断，不能通过配置把损坏或不对应的响应变成可用答案。
- 查询次数、并发、超时和清理必须有边界；失败和回退应可追踪。

## 缓存

- 第一版缓存上游原始响应，不建立通用最终响应缓存。
- 命中缓存后仍执行后续规则和请求相关的改写。
- 缓存键区分上游及影响响应的查询参数，不仅是域名和查询类型。
- 遵循 TTL、负缓存和响应身份处理要求；不能把事务 ID 等某次请求状态直接泄漏给下一次请求。
- 缓存中的原始数据不能被规则就地修改，避免污染其他查询。
- 第一版不因普通 DNS 缓存而强制引入额外持久化服务。

## ECH 与响应改写

- ECH 来源由规则明确选择：直接配置、DNS HTTPS 记录或主动 TLS retry-config 探测。
- 不绑定 Meta 或其他厂商，不隐式启动探测或下载配置。
- 主动探测复用库的认证参数。按 2026-10-23 使用者修订，verifyCertificate 默认 false；可显式 true 开启，开启后不因 CPU 或认证失败自动降级。
- 获取、缓存和刷新行为必须显式且有日志；过期配置不能被无声当作新结果使用。
- 普通查询应避免重复执行完整探测；具体触发和复用策略在动作设计中落实。
- 修改答案时清除 AD，并移除因修改失效的相关签名；不伪造 DNSSEC 认证。
- 未修改的记录和响应不应因统一序列化而无故丢失协议信息。

## 交付阶段

### 第一阶段：规则模型与执行器

交付：
- 类型化配置、上下文、条件、规则集和多动作模型。
- 内置条件组合与函数扩展入口。
- 当前状态、只读原始数据、继续/停止/返回控制。
- 必需/可选失败策略、动作级回滚、结构化错误日志。
- 使用替身上游和 DNS 测试数据验证，不先依赖公网服务。

验收：
- 规则及动作顺序可观测；未命中规则不产生动作副作用。
- 后续条件能读取前序修改后的状态。
- 可选动作部分修改后失败，状态恢复、错误可见，后续动作继续。
- 必需动作失败不返回半成品；终止与默认上游行为明确区分。
- 自定义条件/动作异常、非法状态和错误配置有确定行为。
- 原有两个基础库回归不退化。

### 第二阶段：可用 DoH 服务

交付：
- 标准 DoH 入口、环境变量规则组加载及排序、可选路径访问密钥。
- DoH 上游、命名上游组、三种查询策略、可配置成功条件。
- 上游原始响应缓存及默认上游收尾。
- 自定义记录与基本响应处理，形成端到端可用服务。

验收：
- 标准客户端可查询，输入错误与 DNS 错误正确区分。
- NXDOMAIN、NODATA、SERVFAIL、超时和竞速选择有独立测试。
- 缓存隔离、TTL、负缓存和原始响应不可变性得到验证。
- 失败回退、请求取消、未采用响应和连接资源得到清理。
- 路径密钥校验与日志脱敏有自动化测试。

### 第三阶段：增强能力与完整验收

交付：
- 完善通用记录改写、TTL、AAAA 控制和 HTTPS/ECH 等内置动作。
- ECH 来源适配和显式获取/复用配置。
- 可选 JSON 接口、完整示例、配置说明及限制文档。
- 免费套餐环境下的代表性线上正确性与 CPU 测量。

验收：
- 内置与自定义动作使用相同的执行、失败、回滚契约。
- 改写结果不残留错误 AD 声明或因改写失效的相关签名。
- ECH 失败按规则处理且记录原因，不自动关闭认证。
- 记录冷/热路径、缓存命中/未命中、规则和动作数量下的 CPU 与 Wall time。
- 单独测量完整 ECH 探测，不能用“后台执行”声称绕过免费 CPU 限额。
- 默认和内置场景满足免费套餐目标后才宣布验收；任意用户函数没有无条件性能保证。
- 若重型路径不达标，应提出优化、分解和明确的取舍供用户决定，不静默移除已约定能力。

分阶段不缩减最终范围，不将第三阶段改称未承诺的未来功能。
