## 结论

**HTTPS/TCP-only 功能范围已有当前源码的有界云端正确性证据；普通配置可按下述边界评估使用，但不能宣称当前完整版本已通过 Free 验收。** 本轮只做证据对账与入口更新，没有新增云端请求、部署、profile、行为测试或生产算法改动，也不修改 GitHub 勾选项、关闭 #25/#7 或推送代码。

这不是再次列出无限测试矩阵。尚未取得的证明与真实故障分开；已覆盖的内容不反复测试。用户认可的政策是“大部分请求满足 Free，允许偶发成功超额”，不是每次 CPU 都必须低于 10 ms，也不是任意裸多数自动验收。没有另造百分比、尾延迟或额外 CPU 配额保证。数值超额、实际 `exceededCpu`、DNS/HTTP 错误与缺失遥测分别记录；历史结果不改写。

## 普通路径与主动 ECH 的实际使用边界

### 普通 DNS、缓存和受控组合规则

- 使用明确配置的 HTTPS/普通 TCP 来源及有界规则、列表、归属操作；不承诺任意规模。空配置不会隐式查询公共解析器，顺序回退必须显式配置。
- 当前正确性和缓存隔离可按上表范围交付。历史普通组合 measured 分别为 **32/32、24/32、33/34** 个 CPU 样本不超过 10 ms；最后一组是 34/38 的未完成计划轮次。它们是三次不同运行，不合并、不当作新版本性能承诺，也不由其中一次较低值宣称优化。
- 历史完整轮的 CPU 中位数 6/10 ms、后续部分轮 6 ms 支持“普通组合不必因为个别超额反复抓 profile”的推进方向；不自动将 24/32 或其他比率定义为用户已批准的验收阈值。实际平台终止、错误响应和缺失观测仍不能算通过。
- 不为那一次尚未稳定复现的 TCP 错误增加默认重试、降级或来源替换。只有形成稳定复现并影响实际用例时，才进入缺陷诊断流程。

### ECH 分开处理

[十次连续未缓存公网探测](meta-uncached-cpu-2026-10-24.md)的默认 CPU 为 **31/13/12/13/13 ms**，显式认证为 **39/27/21/23/24 ms**；十次均超过 10 ms。[后续旧基线](online-results-2026-10-25.md)的四次未缓存值为默认 **57/21 ms**、显式认证 **110/35 ms**。这是反复出现的高成本，不应套用“允许偶发个别超额”来宣称逐请求完整探测适合 Free。

历史 ECH 缓存命中有 **8/7/5 ms** 的关联 CPU 观察，但首次 miss/acquired 仍有高成本，一条认证缓存样本缺原生指标；缓存命中不能替代未缓存验收。普通原始 DNS 缓存和 ECH 配置缓存是两个不同机制，不能互相冒充。

因此：直接配置 ECH、从 DNS HTTPS 来源取得 ECH，以及复用已有探测缓存，应与每个 DNS 请求都主动握手的用法分开评估。这里是使用边界，不是自动删功能、改默认或限制配置。默认 `verifyCertificate:false` 保持既有契约；要求证书认证的用例须显式 `verifyCertificate:true`，失败时不能自动关闭验证。所有模式仍需 CertificateVerify/Finished 和完整握手。

## 真正影响进一步发布声明的有限缺口

| 想作出的声明 | 还缺什么 / 处理方式 |
| --- | --- |
| “当前版本已经过 Free 性能验收” | 当前哈希下、实际代表普通工作负载的原生 CPU/Wall 证据。没有这份证据，就保持有条件使用说明；不以旧数值替代，也不要求先解决 profile API。若后续决定补测，只补代表用例，不重跑全矩阵。 |
| “每个请求主动、未缓存 ECH 也适合 Free” | 已有相反的重复成本证据。可选择不作此承诺并接受已说明的使用边界，或单独立项做有复现/收益证据的优化；不默默删掉功能或降低认证。 |
| “当前完整回归与完整安全组合全部通过” | 当前版本全套回归执行记录，以及要承诺的具体尚缺负例（例如 HTTPS 错误证书、签名 DNSSEC 改写组合）。只在确需该声明时安排获授权云端验证，不能要求无限组合，也不把缺证据伪装成已知缺陷。 |

这三类缺口不阻止交付已有有界正确性结果，但阻止相应更强的发布承诺。路径密钥、此次来源/查询/Secret 目标缓存隔离、DoT 取消及 profile 404 不再反复作为“尚未做任何验证”的笼统理由。历史缺测、不适合的 TTL 精确断言、旧 DoT 错误和一次 TCP 失败继续保留，不重新标绿。跨 colo、精确冷 isolate、可靠 p95/p99、任意列表/规则规模不属于当前可承诺范围。
