# 环境变量驱动的可自定义 DNS 服务

日期：2026-10-19。
GitHub Issue：https://github.com/aloneowo0/SuperDoH/issues/7。
状态：需求与测试接缝均已确认；项目技能配置已完成，本规格是完整目标范围，不是全部实现已完成声明。

2026-10-20 实施快照：T1 / #8（`26befc2`）、T2 / #9（`72b919b`）、T3 / #10（`2f895ce`）已提交并通过本地 workerd/类型/DNS/ECH 回归。可用接口与限制见 [规则执行器文档](../rules.md)；正式 DoH、上游、缓存、来源及其他后续切片仍未交付，未部署，线上免费 CPU 配额尚未验收。
领域语言以项目词汇表为准。本文取代此前规划中与最终决策冲突的文件配置、Bearer 请求头和旧域名列表回退方案。

## Problem Statement

部署者需要一个运行在 Cloudflare Workers 免费套餐上的可自定义 DNS 服务，而不是旧版业务策略的复刻。

部署者希望在 Workers 环境变量里按组维护规则，根据域名、客户端及解析结果的 IP、ASN、地区等条件，按明确顺序执行多个动作，包括查询上游、生成自定义答案、改写记录和设置 ECH。现有通用 DNS WASM 与 ECH 探测库提供基础能力，但还没有组合这些能力的规则执行器与新 DoH 应用。

配置和执行必须可预测：规则能组合但不隐式联网，失败必须可见，可选动作不能留下半修改状态，外部域名列表更新失败不能静默沿用旧数据。免费套餐兼容性需要真实 CPU 测量，不能由本地测试或网络经过时间代替。

## Solution

建立单部署、单套 DNS 配置的规则驱动 DoH 服务。全部应用配置来自 Workers 环境变量，敏感值使用 Secret。每个规则组独立保存为 JSON 变量并带排序参数；规则组、组内规则和规则内动作都有确定执行顺序。

提供声明式条件与内置动作，也允许在代码中注册受信任的条件和动作函数，由 JSON 按名称及参数引用。请求经过同一规则流水线，上游原始响应可缓存，但缓存不绕过本次请求的规则。

支持标准 DoH、可选 JSON 适配、单上游/顺序回退/并发竞速、路径访问密钥、外部域名列表、显式响应地址归属补全及规则指定的 ECH 来源。先交付执行器，再形成可用 DoH，最后完善增强能力和免费套餐验收；分阶段不缩减最终范围。

## Implementation Decisions

### 配置与规则组

- 只有环境变量配置来源，不保留文件配置回退。敏感值由 Secret 提供，普通 JSON 仅引用敏感绑定名。
- 每个规则组是独立 JSON 变量，包含排序参数和规则数组。公共上游、来源和默认策略同样通过环境变量配置。
- 支持平台 JSON 值或经解析的 JSON 文本，统一进入同一校验和执行模型。
- 对此前尚未冻结的命名细节，采用初始约定：规则组变量前缀 DNS_RULE_；order 为必填整数，升序执行，同序号按变量名稳定排序。这是规格化默认值，不是声称此前示例 API 已实现。
- 组内规则和动作按数组顺序执行。变量名成为稳定的诊断标识，不依赖环境变量枚举顺序。
- 校验结构、字段、条件/动作类型和上游、列表、扩展引用；错误明确报告，不默默忽略或回退。
- 兼顾单变量 5 KB 和免费套餐普通变量与 Secret 合计 64 个的限制；环境变量不是无限列表存储。
- 运行时变量不同于构建变量。面板修改需要保存并部署相应配置，不宣称每个请求实时读取控制台。后续部署不得意外覆盖面板维护的变量。

### 匹配与扩展

- 条件以字段、操作符和参数表达，支持 all/any/not，提供明确的比较和集合量词语义。
- 支持查询、客户端、当前响应、已补全的响应地址属性和边缘信息，不以厂商或少数业务场景为白名单。
- 域名匹配遵守标签边界，区分含自身后缀和仅子域。区分当前/原始查询名、记录所属域名和 CNAME 等目标。通配符单级/多级边界和正则语义在实现接口文档中明确并测试，不以字符串包含代替域名匹配。
- 客户端 ASN/地区可来自平台入站元数据；响应 IP 的归属不能由入站字段冒充。地区精度和缺失状态如实反映来源能力。
- 地址归属补全是显式动作，来源由配置指定，可缓存。匹配条件不隐式联网。
- 多地址条件支持同地址绑定和明确的任意/全部语义，避免跨地址误命中。
- 受信任扩展随代码部署，由 JSON 按名称引用。它不是不可信代码沙箱，不接受请求上传代码，不以 eval 或动态函数构造执行字符串。
- 每条规则进入时判断一次条件。函数抛错或来源不可用不能伪装成普通未命中；不存在的普通属性使用明确存在性和比较语义，不补造值。

### 执行、状态、终止和错误

- 每条规则可含多个顺序动作；上游查询、答案生成和响应改写都是动作。新查询由配置明确触发，没有隐式阶段重跑或默认递归。
- 查询动作默认以取得的响应作为当前响应，不隐式合并多个答案；需要合并时显式表达。原始数据只读，不通过共享引用污染缓存。
- 后续动作和规则读取当前状态，同字段以后执行的成功修改为准。
- 默认继续；停止后续规则进入统一收尾，无答案仍可查询默认上游；直接返回必须已有明确响应，否则报错，不隐式补查。
- 正常结束仍无响应时查询默认上游，失败返回 SERVFAIL；合法 NXDOMAIN 和 NOERROR 空答案属于已有响应。
- 必需动作失败默认终止并返回 SERVFAIL。显式可选动作失败时回滚自身 DNS 工作状态，记录错误并继续。之前成功动作不回滚，网络请求和已写日志不承诺撤销。
- 自定义动作使用相同的工作状态、校验和回滚契约，不得通过共享引用破坏原始数据或留下半修改结果。
- 所有输出经过统一协议和 DNSSEC 一致性收尾，扩展与提前返回不能绕过。
- 日志关联请求、规则组、规则和动作，记录错误码、信息、可用原因链及回滚/继续/终止/回退处置。可选失败和成功回退不得抹去先前错误。
- 不直接转储配置、密钥、认证信息、完整敏感 URL 或完整 DNS 报文；错误文本同样脱敏，详细诊断需显式控制。

### 域名列表

- 支持直接配置和明确指定的外部 HTTPS 列表。首版格式为一行一个域名的纯文本和 JSON 域名数组。
- 列表只是数据，不是远程代码或带动作的规则集；规则决定如何匹配列表，不靠猜测格式改变语义。
- 显式描述来源及获取、更新策略，匹配不在每次判断时偷偷下载。
- 下载及完整校验成功后完整替换，不暴露部分更新数据。
- 更新失败直接标记来源不可用，即使旧版本仍在缓存也不得继续使用。首次失败、HTTP 失败及校验失败均报错，不当空列表或未命中。
- 依赖不可用来源的处理默认失败并记录原因；仅明确的失败策略允许继续，不得将错误自然降为条件 false。
- 后续成功更新并校验后恢复使用。更新间隔不是 DNS TTL。实现明确失效作用域、跨实例可见性和重试边界，不以进程内状态声称全局一致。

### 接口与访问控制

- 标准接口支持 RFC 8484 GET/POST 和 DNS wire-format；可选 JSON 适配复用同一核心。
- 单部署单配置，不实现多用户账户。
- 密钥可选：配置后保护入口，否则公开。仅通过路径携带，不要求 Bearer 请求头，也不放在查询参数中。
- 密钥来自 Secret；认证在规则执行及非必要工作之前完成。应用日志隐藏密钥路径，不保证外部代理或客户端不记录 URL。
- 无效 HTTP/DoH 输入和合法查询的 DNS 执行失败分别处理，不将所有错误包装成 DNS 成功响应。

### 上游与缓存

- 首版上游为标准 DoH。命名组支持单个、顺序回退和并发竞速，由规则动作引用。
- 采用条件可修改，有默认值。默认接受对应查询的有效 NOERROR 和 NXDOMAIN，包括合法空答案；不以 HTTP 200 为充分条件，SERVFAIL/REFUSED 默认不成功。
- 协议有效性先于自定义采用条件；不能允许配置将损坏或不对应的响应变成合法答案。
- 竞速采用首个符合条件的响应，未采用请求及时取消、清理；全部失败保留可诊断原因。
- 只缓存上游原始响应，命中后仍执行本次规则，缓存对象不得被动作污染。
- 缓存身份包含上游及影响答案的参数，涵盖适用的 EDNS/ECS、DO/CD；不能只按域名或域名加类型共享所有结果。
- 正确递减 TTL、执行负缓存规则、恢复本次请求关联信息。故障结果及无法安全复用的查询不自动缓存。
- 不把边缘缓存当作保证命中、永久保存或全局一致的数据库，不为基础缓存强制引入额外持久化服务。

### ECH、改写与资源

- 复用通用 DNS WASM 与 ECH 探测库，业务策略不写回基础库。
- ECH 来源按规则选择：直接配置、DNS HTTPS 记录或主动 TLS retry-config 探测，不绑定厂商或隐式启动探测。
- 获取时机和复用策略显式配置，普通查询不默认重复完整握手。ECH 有效性策略与域名列表更新失败即失效的政策分别建模，不混为全局缓存策略。
- 主动探测沿用默认开启的认证，失败记录原因；不能为适配 CPU 自动关闭认证或静默采用不可信替代来源。
- 改写后清除 AD，移除因改写失效的相关签名；未修改数据保留适用信息，不宣称改写答案继承原 DNSSEC 认证。
- 输入、列表大小、网络次数、并发、总耗时和处理工作有可配置边界及保守默认值。扩展函数不意味着无限资源，同步死循环不能仅靠 Promise 超时可靠终止。
- 免费套餐是默认和内置场景的验收要求，不是对任意用户函数的无条件性能保证；后台和 Cron 不解除平台 CPU 限制。

### 分阶段交付

1. 规则模型与执行器：配置模型与校验、组合条件及命名扩展、顺序多动作、当前状态与只读原始数据、终止、失败、回滚和日志。先用确定性输入、动作与来源验证，不宣称已形成网络服务。
2. 可用 DoH：标准入口、环境变量规则组加载和排序、可选路径密钥、上游组及采用条件、原始响应缓存、默认上游、自定义答案和基本改写。
3. 完善和完整验收：域名与归属来源适配、完整内置改写、规则指定 ECH 来源、可选 JSON 入口、配置和部署说明、真实互操作及免费套餐测量。

各阶段有行为验收，第三阶段不是未承诺的未来功能。不达标时报告实测和取舍，不静默删功能。

## Testing Decisions

### 验收接缝：已由用户确认

- 以 workerd 中公开的 DoH 请求入口作为主要应用验收接缝：发送真实 HTTP/DNS 输入，提供环境变量，观察响应报文、测试上游收到的查询、来源请求和脱敏错误事件。
- 本规格制定时执行器尚不存在；阶段一采用最小公共执行接缝（现由 executeQuery 提供）：输入查询上下文和规则配置，观察结果和外部事件；不为每个内部辅助模块增加测试接口。
- 阶段二以后尽量将跨模块断言上移到同一 DoH 入口。上游、列表、归属来源和时间使用可控替身或本地服务，不要求普通测试依赖公网。
- 复用现有 Miniflare/workerd 请求驱动测试的方式和独立 OpenSSL 互操作经验，保留两个基础库回归；不重建一套测试专用生产 API。

### 好测试的标准

- 只断言外部可观察行为、有效协议输出、副作用和错误处置，不锁死私有函数、内部对象布局或实现步骤。
- 控制时间、超时、并发完成顺序和来源更新结果，让状态转移可重现。
- 通过输出重新解码、请求响应关联验证及独立本地服务检查关键协议行为，避免同一实现生成预期后自证正确。

### 行为覆盖

1. 配置：独立规则组，排序及相同序号，规则/动作顺序，结构和引用错误，无文件回退、无字符串代码执行。
2. 条件：组合逻辑、域名边界、当前与原始域名、查询类型、客户端与边缘区别、缺失属性、同地址关联、归属补全前后，条件错误不等于未命中。
3. 状态：前序修改影响后续匹配、原始数据只读、生成答案不自动返回、停止与返回不同、默认上游、空答案不多查。
4. 失败：必需动作终止，可选动作半修改后恢复自身状态，前序成功动作保留，扩展动作同样回滚，外部副作用不伪装成可撤销。
5. 日志：每次失败与处置可定位，路径密钥、上游凭据及错误文本脱敏，不靠静默回退通过测试。
6. 列表：两种格式、首次失败、HTTP/校验/部分下载失败、完整替换、更新失败即使旧缓存仍在也不可用、不当空集、更新成功恢复，明确测试失效作用域。
7. 上游：单个/回退/竞速、有效 NXDOMAIN/NODATA、自定义采用条件、SERVFAIL/REFUSED、损坏和不对应响应、全部失败、取消及清理。
8. 缓存：命中仍运行规则、TTL 递减和负缓存、上游与参数隔离、请求身份恢复、不可变性、不安全查询绕过缓存。
9. 入口：GET/POST、可选 JSON 同核行为、输入错误、无密钥和正确/错误路径密钥、拒绝时无上游副作用、所有返回路径统一收尾。
10. 改写：固定记录、地址/TTL/AAAA/HTTPS、AD 与相关签名处理、三类 ECH 来源、认证失败不降级、获取失败按策略处理、原始缓存不污染。
11. 运行环境：不启用 nodejs_compat 的 workerd 回归、严格类型检查、浏览器目标构建及基础库回归，不能仅凭 Node 通过宣称 Workers 可用。
12. 性能：线上免费环境分别测量冷/热路径、缓存命中/未命中、不同规则规模、来源加载/更新和主动探测的 CPU、Wall time、分布与资源错误，不只给平均网络耗时。

## Out of Scope

- 自动继承旧功能、旧 AUTO 流程、厂商专用路由和旧代码架构。
- 文件配置回退、在线配置数据库、可视化管理页面和配置深度合并系统。
- 多账户、多租户、多配置入口和权限管理。
- Bearer 请求头或查询参数密钥方案、伪装网站入口。
- 不可信脚本沙箱、请求上传代码、运行时字符串求值。
- 首版完整兼容 hosts、Adblock、Clash/Mihomo 规则语义。
- 任意上游传输协议、通用应用 TLS 会话、通用最终答案缓存、自行签发 DNSSEC 或冒充原签名有效。
- 隐式自带全球响应 IP 归属库、默认厂商 ECH 来源、更新失败沿用旧域名列表。
- 保证任意自定义函数不超 CPU、保证进程缓存跨所有边缘全局一致、将本地测试等同线上额度证明。
- 本次 spec 自动开始实现、提交、推送或部署；线上资源和验收另行授权。
